5. Contrat de verdict_icmp (3 points)

La couche L3 est considérée OK si au moins 50 % des sondes ICMP ont reçu une réponse. 

def verdict_icmp(nb_reponses: int, nb_sondes: int) -> Verdict:
    """
    PRE : ...

    POST : ...
    """

Correction

PRE : nb_sondes > 0 ;
      0 <= nb_reponses <= nb_sondes.

POST : renvoie Verdict.OK si
       nb_reponses >= nb_sondes / 2,
       Verdict.KO sinon.
       Ne modifie rien.

6. Contrat de retirer_page (3 points)

La méthode retire une page du site. La page principale ne peut pas être supprimée. Si aucune page ne porte le nom demandé, une ValueError est levée. En cas d'exception, le site reste inchangé. 

def retirer_page(self, nom: str) -> None:
    """
    PRE : ...

    POST : ...

    Exceptions :
        ...
    """

Correction

PRE : aucune.

POST : le site ne contient plus de page nommée nom ;
       les autres pages et leur ordre sont inchangés.

Exceptions :
    ValueError si aucune page ne porte ce nom ;
    ValueError si nom désigne la page principale.
    Dans ces cas, le site n'est pas modifié.

9. Fonction pure ou non ? (2 points)

def calculer(a, b):
    return a + b

def afficher(a, b):
    print(a + b)

Indique si chaque fonction est pure ou non. Justifie ta réponse.

Correction

calculer : fonction pure. Le résultat dépend uniquement des paramètres, les mêmes entrées donnent le même résultat et aucun effet de bord n'est produit.

afficher : fonction non pure. print() produit un effet de bord en affichant une information dans la console.

10. Les cinq principes de testabilité (2 points)

Explique les cinq principes suivants :

  • Contrôlabilité
  • Observabilité
  • Déterminisme
  • Isolation
  • Oracle explicite

Correction

  • Contrôlabilité : placer l'objet dans la situation souhaitée.
  • Observabilité : pouvoir lire le résultat produit.
  • Déterminisme : mêmes entrées, même résultat.
  • Isolation : tester sans dépendre inutilement du réseau ou de l'interface.
  • Oracle explicite : connaître le résultat attendu grâce au contrat.

11. Précondition forte et faible (1 point)

Quelle est la différence entre une précondition forte et une précondition faible ? Donne un exemple avec moyenne.

Correction

Une PRE forte impose à l'appelant de respecter une condition avant l'appel.

Exemple : PRE : durees n'est pas vide.

Une PRE faible impose moins de contraintes : la méthode gère elle-même le cas problématique.

Exemple : PRE : aucune, puis ValueError si la liste est vide.

12. Séparation interface / métier (1 point)

Où placer input(), print() et la logique métier ? Que faire lorsqu'une méthode métier lève une exception ?

Correction

input() et print() appartiennent à l'interface. Les règles et traitements appartiennent à la partie métier.

L'interface appelle le métier, récupère les exceptions avec try/except et affiche un message compréhensible.
